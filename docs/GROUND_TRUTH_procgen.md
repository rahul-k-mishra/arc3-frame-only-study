## Registered truth definitions (PREREG.md v1 copies these verbatim)

From docs/GROUND_TRUTH_minigrid.md, where they apply:
- A1 holds iff at least one action changes the rendered frame and different actions can change it differently.
- A2 holds iff exactly one rendered object's displacement is a deterministic function of the action (the agent).
- A4 holds iff every zero-displacement move is explained by the cell ahead holding an object that cannot be overlapped, and that set of blocking objects changes only through the agent's own actions.
- A5 holds iff the episode terminates with success when the agent enters a specific cell, with no facing requirement and no non-move action.
- Termination by failure (lava, wrong object in Memory, max steps) is recorded in the predicate column and does not count as a level end.

Additions for pixel physics:
- A2 holds iff exactly one entity's motion is a deterministic function of the action (the agent); if the agent is present but other entities also respond to the action, say so and record A2 as failing.
- A3 holds iff each movement action, when unblocked, displaces the agent by a constant vector regardless of position and history. Velocity that persists across steps, acceleration, gravity, or a jump arc all fail A3. Record from source how the agent's position is updated per action (the velocity assignment, any gravity term, any momentum), and quote the line.
- A4 holds iff every zero-displacement move is explained by a fixed set of wall or obstacle cell types present at level start that changes only through the agent's own actions; an obstacle that moves on its own fails A4; an entity that kills on contact rather than blocking is recorded under the termination predicate and does not affect A4.
- A5 holds iff the level completes when the agent's position enters a specific region, with no other condition at that moment; a completion that requires collecting a set of items, defeating enemies, or surviving a duration fails A5; a completion that requires reaching a region only after a precondition has been met elsewhere (a gem behind a key) holds A5 with the precondition recorded.
- Level semantics: record what procgen does on level completion under the two constructor settings — num_levels 1 with the same start_level (the level replays) and use_sequential_levels true (the next level begins without an episode reset) — from game.cpp and the game's own reset code, with the line. PREREG.md will register one of the two for the confirmatory runs; do not choose.
- Also record per game: which info-dict key reports completion and from which source line it is set; whether the 15 actions are all distinct for this game or some are duplicates or no-ops (from the game's action handling), with the line.

## Level semantics (the finding PREREG.md must register one side of)

- **On completion**, the game sets step_data.level_complete = true and step_data.done = true (in each game's row). Game::step then calls reset() (game.cpp:144-145).
- **Setting 1: num_levels 1, fixed start_level s.**
  - vecgame.cpp:290-292 sets level_seed_low = s and level_seed_high = s + num_levels = s + 1.
  - reset() draws `current_level_seed = level_seed_rand_gen.randint(level_seed_low, level_seed_high)` (game.cpp:101), which is always s, then `rand_gen.seed(current_level_seed); game_reset();` (111-112).
  - The same level is regenerated from the same seed and replays from its start.
  - The `first` flag is 1 on that step (game.cpp:161). `prev_level_complete` is 1 on the completing step and 0 after a death or timeout.
- **Setting 2: use_sequential_levels true** (a BaseProcgenEnv keyword, installed procgen/env.py:80).
  - On completion, reset() takes the branch `if (options.use_sequential_levels && step_data.level_complete) current_level_seed = (int32_t)(current_level_seed + 997);` (game.cpp:97-99), so the next level has a new seed.
  - Game::step then clears done: `if (options.use_sequential_levels && step_data.level_complete) step_data.done = false;` (game.cpp:148-150). No episode boundary is signalled (`first` = 0), and the next level begins in the next frame. The only completion signal is `prev_level_complete` = 1.
  - A death or timeout still ends the episode, and reset() draws a seed from [low, high) again (game.cpp:101). With num_levels 1 that returns the run to level s.
- **What this means for the census and G** (not a choice):
  - Under setting 1, every level end replays the same level, so a place goal recorded at one end can be retested on the same layout.
  - Under setting 2, each level end moves to an unseen level (seed + 997), so a place hypothesis does not carry over. Only a feature hypothesis can.

## Limits and findings for PREREG.md

1. **Camera.** center_agent is True by default in ProcgenGym3Env (procgen/env.py). W0 check C2 did not set it. Six games keep it and scroll the world under a centred agent: caveflyer, climber, coinrun, fruitbot, jumper, ninja. On frame differences the agent then barely moves while the background shifts. The census's A2/A3 frame probes would see the world, not the agent, move. PREREG.md must register center_agent for suite C (False for all games, or per game). This is a registered adapter setting, not a truth value; the truth above is about game state.
2. **The completion key is `prev_level_complete`** (game.cpp:163). The suite-C adapter must read that key as level_end. There is no `level_complete` key.
3. **Actions.** 15 actions are exposed, but many are duplicates or no-ops per game (actions column). The registered action list for suite C should be recorded per game from this table. The census's A1 "different actions change it differently" is evaluated over distinct actions only.
4. **A3 fails on 14 of 16 games by construction** (momentum, gravity, hops, persistent velocity). Suite C is therefore mainly an A3-fails suite, which is its purpose (the non-lattice test).
5. **Level semantics.** Setting 1 (num_levels 1) replays the same level after every completion and every failure. Setting 2 (use_sequential_levels) moves to seed + 997 on completion without an episode boundary. The choice is left to RKM, as instructed.
6. **Sources were read at tag 0.10.7**, the version installed in .venv_procgen (W0 check C1). The installed wheel's compiled library was not inspected. The tag is taken as its source because the package version matches.
