# GROUND_TRUTH_minigrid.md — suite B ground truth from source

Written 27 September 2026 (W1). This file is the V1 answer key and the per-environment prediction for suite B (MiniGrid + BabyAI). It is committed before any census or agent run on suite B.

**Source.** Only the installed package minigrid 3.1.0 at D:\Research\arc3\brutus\.venv_games\Lib\site-packages\minigrid\ was used. No documentation pages and no memory. File paths below are relative to that folder, and line numbers are those of the installed files.

**How the table was built.**
- The id list is the registry: 172 register() calls in __init__.py, plus six WFC presets registered in a loop (__init__.py:567 → envs/wfc/config.py:533-540) — 178 ids, 82 MiniGrid- and 96 BabyAI-.
- The truth values were read by hand, once per entry-point class and its step() override (MiniGrid) or instruction verifier (BabyAI).
- A formatting script then joined each id to its class row. It lives in the session scratchpad, is not a repository script, and reads nothing but __init__.py.

## Registered truth definitions (PREREG.md v1 copies these verbatim)

- A1 holds iff at least one action changes the rendered frame and different actions can change it differently.
- A2 holds iff exactly one rendered object's displacement is a deterministic function of the action (the agent).
- A3-raw: under the primitive action set (turn left, turn right, forward, pickup, drop, toggle, done), holds iff each action's displacement of the agent is constant across positions and facings. Expected false everywhere because forward depends on facing; record it from source, not by assumption.
- A3-macro: under the absolute-move macro (north, south, east, west, each a turn-to-face then forward), holds iff each macro's displacement is constant when unblocked.
- A4 holds iff every zero-displacement move is explained by the cell ahead holding an object that cannot be overlapped, and that set of blocking objects changes only through the agent's own actions (a door opened by toggle counts as agent-caused; an obstacle that moves on its own, as in Dynamic-Obstacles, fails A4; lava does not block, it terminates, so it is recorded under A5 and does not affect A4).
- A5 holds iff the episode terminates with success when the agent enters a specific cell, with no facing requirement and no non-move action; terminates-on-adjacency, terminates-on-pickup/drop/toggle/done, and terminates-on-facing all fail A5. Record the exact predicate and where it is evaluated (the env's step or the BabyAI verifier), with file and line.
- Termination by failure (lava, wrong object in Memory, max steps) is recorded in the predicate column and does not count as a level end.

## Limits and findings for PREREG.md

1. **Several columns have no variance on suite B.** A1, A2 and A3-macro hold on every id, and A3-raw fails on every id; all four follow from the shared step() and renderer. A4 fails only on the 6 Dynamic-Obstacles ids (6 of 167 non-excluded). Cohen's κ is undefined, or degenerate, when the truth column is constant. So the V1 row "agreement ≥ 0.90 and κ ≥ 0.70 per assumption per suite" cannot be applied as written to A1, A2, A3-raw and A3-macro on suite B, and on A4 it rests on 6 positives. PREREG.md must register what V1 means for a constant truth column — for example agreement only, with κ reported as not defined — before any run. This is a decision for RKM, not made here.
2. **A5 is decided per environment class, not per instance.** The goal cell varies by seed in FourRooms (random goal), MultiRoom (goal placed at random in the last room) and Memory (cue-dependent), but in every instance the predicate is "enter a specific cell". For G, Memory's success cell changes with the cue across episodes, so a place hypothesis learned in one episode does not carry over.
3. **Failures in the predicate column are not level ends:**
   - lava (B-lava);
   - Memory's failure cell;
   - Fetch's and PutNear's wrong pickups;
   - GoToDoor's and GoToObject's toggle and wrong done;
   - Dynamic-Obstacles' bump (reward −1);
   - RedBlueDoors' wrong order;
   - BabyAI verifier failures;
   - max steps (B-trunc).
4. **Playground has no success termination at all** (no Goal placed; only truncation). It fails A5, and V2's level-1 outcome is "not completed" by construction.
5. **BabyAI done actions are off by default** (verifier.py:26 reads the environment variable BABYAI_DONE_ACTIONS). The truth above assumes it is unset. The suite-B adapter must register that it is unset.
6. **Under the macro condition, a turn inside a macro can complete a BabyAI GoToInstr**, because the verifier checks after every action. This changes when success happens, not the A5 verdict: facing is required, so A5 fails.
7. **The WFC truth values come from source only.** They could not be checked by construction (W0_CHECKS.md amendment (b)), and those ids are excluded.
